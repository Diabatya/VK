# xDrip to VK

Android-приложение для автоматической отправки данных уровня глюкозы, инсулина и углеводов из xDrip+ в чат ВКонтакте и/или MAX.

## Особенности

- **Приём данных**: через Broadcast от xDrip+ и через локальный веб-сервер xDrip+ (`127.0.0.1:17580`)
- **Два независимых канала отправки**: ВКонтакте (VK API `messages.send`) и MAX (ответом на уведомление в выбранный чат)
- **Надёжный фон**: `AlarmManager` + `WakeLock` — работает даже при сворачивании и в Doze Mode
- **Автозапуск**: при загрузке устройства, если настроены токен и чат
- **Тревожные сообщения**: отдельный чат для оповещений о низком/высоком сахаре
- **Терапия**: разовые уведомления при вводе инсулина/углеводов + расчётные остатки (IoB/COB) в каждом сообщении
- **Многострочный формат**: имя устройства, глюкоза со стрелкой тренда, активный инсулин, активные углеводы
- **Современный интерфейс**: Material Design 3 — большая карточка с сахаром, цветовая индикация, Floating Action Button, Chip статуса
- **Повтор при ошибке**: автоматические попытки отправки (5, 10, 20, 40 секунд)
- **Выбор чатов из списка**: загрузка бесед ВКонтакте с отображением названий

## Требования

- Android 8.0 (API 26) или выше
- Установленное приложение **xDrip+**
- Включённый **веб-сервер** в xDrip+ (меню → Настройки → Между приложениями → xDrip Web Service → Включить, порт 17580) — это единственный источник значений сахара
- Разрешённые **Broadcast** в xDrip+ (меню → Настройки → Между приложениями → Local Broadcasts) — broadcast является **только сигналом для опроса** веб-сервера, данные из него не берутся
- Для канала **VK**: токен VK API с правом `messages` и выбранный чат
- Для канала **MAX** (независимо от VK, реквизиты VK не нужны): установленный MAX, доступ к уведомлениям для этого приложения, выбранный чат MAX и свежее уведомление из него (кнопка «Ответить»)

## Установка

1. Скачайте APK `caxarok_<версия>.apk` (например, `caxarok_4.3.1.apk`)
2. Установите на Android-устройство
3. Разрешите все запрошенные разрешения (уведомления, автозапуск)

## Настройка

1. Откройте приложение → **Настройки** (шестерёнка)
2. **Токен VK** — введите токен доступа VK API
3. **Чат для сообщений** — нажмите "Выбрать чат", приложение загрузит список бесед
4. **Чат для тревог** (опционально) — отдельный чат для оповещений
5. **Единицы измерения** — ммоль/л или мг/дл
6. **Имя устройства** — будет показано в сообщениях как заголовок
7. **Интервал опроса** — как часто опрашивать xDrip+ (рекомендуется 5 минут)
8. **Тревожный диапазон** — минимальное и максимальное значение глюкозы
9. Вернитесь назад и нажмите **«Запустить сервис»**

## Получение токена VK API

1. Перейдите на https://vk.com/dev/access_token
2. Создайте или выберите приложение
3. Укажите права: `messages`
4. Скопируйте полученный токен и вставьте в настройки приложения

## Формат сообщений

### Регулярное сообщение (каждые 5 минут)
```
Имя устройства
Глюкоза: 5.2 ↑ ммоль/л (10:15)
Инсулин активный: 2.3 ед
Углеводы активные: 12г
```

### Разовое сообщение (при вводе терапии)
```
Имя устройства: Введён инсулин 5.2 ед
Имя устройства: Съедено 45г углеводов
```

### Тревожное сообщение
```
Имя устройства
⚠️ ТРЕВОГА! Низкий сахар!
Глюкоза: 3.1 ↓ ммоль/л (10:15)
Инсулин активный: 2.3 ед
Углеводы активные: 12г
```

## Как это работает

### Источник данных

- Единственный источник значений — локальный веб-сервис xDrip+ `http://127.0.0.1:17580` (`sgv.json`, `devicestatus.json` для IoB/COB).
- **Broadcast от xDrip+ — только сигнал** «данные обновились, пора опросить»: сами значения из broadcast не используются.
- Периодический опрос (fallback): `AlarmManager` будит сервис с выбранным интервалом (рекомендуется 5 минут).

### Два независимых канала отправки

- **VK** — `messages.send` в выбранную беседу (нужны токен и чат VK).
- **MAX** — регулярный текст показания уходит «ответом из уведомления» в один выбранный чат MAX. Реквизиты VK не требуются; отдельные тревоги и сообщения о терапии в MAX **не отправляются**.
- Переключатели «Отправлять в VK» / «Отправлять в MAX» работают независимо. Общий **Stop** («Остановить сервис») блокирует оба канала, включая отложенную отправку.

### Канал MAX — как настроить и что ожидать

1. В настройках откройте **«Доступ к уведомлениям MAX»** и разрешите слушатель уведомлений.
2. Дождитесь **нового сообщения из нужного чата MAX** — оно даёт кнопку «Ответить».
3. Выберите чат в **«Чат MAX»**. Показание уходит при следующем обновлении сахара.
4. Кнопка живёт до перезапуска/смены уведомления: если отправка стала невозможна, последнее показание ждёт **не более 15 минут** от времени измерения.
5. Успех `PendingIntent.send` означает только «передано в MAX» — доставка в чат не гарантируется; при прерывании процесса исход предыдущей передачи может быть **неизвестен**, тогда повтор автоматически не выполняется (отображается «исход неизвестен»), а следующее новое показание отправляется обычным путём.
6. Если у другого чата оказалась та же системная операция ответа, отправка блокируется до нового уведомления выбранного чата — это защита от ответа не туда.

### Жизненный цикл

- `BgReceiver` получает broadcast → будит `VkSenderService` на опрос
- `VkSenderService` опрашивает веб-сервис, формирует сообщение и отправляет в VK и/или MAX
- Если broadcast не приходит — `AlarmReceiver` будит сервис через `AlarmManager`
- `BootReceiver` автоматически запускает сервис при включении телефона
- **Фоновая работа ограничена Android**: Doze, фирменные энергосбережения и ручная «остановка» приложения могут прервать доставку — гарантии работы на любой прошивке нет. Разрешите автозапуск и фоновую активность в настройках телефона.

### IoB и COB

- **IoB** (Insulin on Board) — активный инсулин, рассчитанный xDrip+ с учётом профиля
- **COB** (Carbs on Board) — активные углеводы, рассчитанные xDrip+ с учётом скорости усвоения
- Данные берутся из `http://127.0.0.1:17580/api/v1/devicestatus.json?count=1`
- Поддерживаются форматы: `openaps.iob.iob`, `openaps.iob.cob`, корневые `iob`/`cob`, `pump.iob`/`pump.cob`

## Разрешения

| Разрешение | Назначение |
|-----------|------------|
| `INTERNET` | Запросы к VK API и xDrip+ веб-серверу |
| `FOREGROUND_SERVICE` | Работа сервиса в фоне |
| `FOREGROUND_SERVICE_DATA_SYNC` | Тип foreground service (Android 14+) |
| `RECEIVE_BOOT_COMPLETED` | Автозапуск после перезагрузки |
| `POST_NOTIFICATIONS` | Уведомление о статусе (Android 13+) |
| `WAKE_LOCK` | Будит процессор на время отправки |
| `SCHEDULE_EXACT_ALARM` | Точные alarm в Doze Mode |

## Структура проекта

| Файл | Назначение |
|------|------------|
| `MainActivity.java` | Главный экран: запуск/остановка сервиса, отображение текущего сахара, стрелки тренда, статуса |
| `VkSenderService.java` | Основной foreground service: получение данных, формирование сообщений, отправка в ВК, тревоги, опрос xDrip+ |
| `XDripWebClient.java` | HTTP-клиент для опроса xDrip+: `sgv.json` (сахар), `treatments.json` (сырая терапия), `devicestatus.json` (IoB/COB) |
| `VkApi.java` | Отправка сообщений через VK API `messages.send` |
| `BgReceiver.java` | BroadcastReceiver: получает данные от xDrip+, типобезопасное извлечение сахара |
| `AlarmReceiver.java` | BroadcastReceiver: обрабатывает сигналы AlarmManager, будит сервис для опроса |
| `BootReceiver.java` | BroadcastReceiver: запускает сервис при загрузке системы |
| `SettingsActivity.java` | Экран настроек: токен, чаты, единицы, интервал, диапазон тревог, канал MAX |
| `max/` (пакет) | Канал MAX: слушатель уведомлений, отправка «ответом», подтверждённое состояние и повторы записи |
| `VkConversationsActivity.java` | Загрузка и выбор бесед ВКонтакте |
| `Logger.java` | Логирование в Logcat с тегом приложения |

## Устранение неполадок

| Проблема | Причина | Решение |
|---------|---------|---------|
| «Нет связи с xDrip+» | Веб-сервер xDrip+ выключен | Включите xDrip Web Service в настройках xDrip+ |
| «Данные устарели» | Сенсор не обновлялся 15+ минут | Проверьте сенсор в xDrip+ |
| «Ошибка отправки» | Неверный токен или нет интернета | Проверьте токен VK и подключение к интернету |
| Не работает в фоне | Энергосбережение системы | Разрешите автозапуск и фоновую активность в настройках телефона |
| Не приходят broadcast | xDrip+ не отправляет или изменил action | Приложение автоматически опрашивает веб-сервер по alarm |

### Соответствующие исходники распространяемого APK

Распространяемый APK — это **debug-вариант** сборки (`assembleDebug`), подписанный
постоянным ключом автора. Соответствующие исходники точной версии:

1. Склонируйте репозиторий и перейдите на ревизию выпуска — тег `v<версия>` или
   SHA коммита, указанный в примечаниях к релизу.
2. Соберите тем же вариантом: `./gradlew assembleDebug`
   (инструменты: JDK 17, Android SDK 34, Gradle wrapper из репозитория).
   Результат — `app/build/outputs/apk/debug/caxarok_<версия>.apk`.

**Границы воспроизводимости**: сборка из тех же исходников воспроизводит код и
ресурсы, но побайтовое совпадение с опубликованным APK не гарантируется
(подпись, метки времени упаковки, версия сборочной системы автора). Собранный
вами APK подписан вашим debug-ключом и **не ставится поверх официального** —
это штатная защита Android. Соответствие конкретного старого APK конкретному
тегу устанавливается примечанием к релизу и не проверялось побайтово.

Приватный ключ подписи распространяемых сборок **не публикуется** и публиковаться
не будет: обновление установленных копий гарантируется тем, что выпуски
подписываются одним и тем же ключом на стороне автора.
